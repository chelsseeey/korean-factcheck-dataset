# korean-factcheck-dataset

정책브리핑 「사실은 이렇습니다」 기반 한국어 사실 검증 데이터셋. 정부 해명자료 190건에서 추출한 512개 주장–근거 쌍과 SUPPORTED / REFUTED / NEI 3분류 라벨로 구성된다.

## 데이터 출처와 수집 기간

| 항목 | 내용 |
| --- | --- |
| 출처 | 대한민국 정책브리핑 「사실은 이렇습니다」 (https://www.korea.kr/briefing/actuallyList.do) |
| 해명자료 게시일 범위 | 2026-08-04 ~ 2026-09-12 |
| 수집 실행일 | 2026-09-13 |
| 수집 건수 | 319건 |
| 사용 건수 | 190건 |

「사실은 이렇습니다」는 언론 보도에 대해 각 부처가 사실관계를 설명하는 코너다. 한 건의 해명자료는 정부가 정리한 **보도 내용** 블록과 그에 대한 **정부 입장** 블록으로 구성되며, 이 데이터셋은 전자를 검증 대상 주장으로, 후자를 판정 근거로 사용한다.

## 구축 절차

1. **수집** — 목록 페이지를 순회하며 상세 페이지를 수집한다. 상세 본문은 HTML에 직접 들어 있지 않고 문서뷰어 iframe이 렌더링하므로, 첨부 PDF에서 본문 텍스트를 추출한다.
2. **구간 분리** — 본문에서 「보도 내용」 표지(`보도 내용`, `보도 매체`, `관련 기사` 등)와 「정부 입장」 표지(`정부 입장`, `<○○부 설명>`, `사실관계` 등)를 찾아 두 구간으로 나눈다.
3. **정제** — 문의처·연락처 블록을 제거하고, 주장 추출 입력으로 쓸 수 있는지 판정한다. 본문 절단 의심(47) / 보도 내용 블록 없음(38) / 기사 제목만 있고 주장 내용 없음(33) / 설명 블록 분할 실패(11) 총 129건을 제외해 190건을 남겼다.
4. **주장 분리** — 보도 내용 블록을 참·거짓을 개별적으로 판단할 수 있는 원자 주장 단위로 분해한다. 의견·전망·평가 표현("우려된다", "비판이 나온다")은 제외한다. 자료당 평균 2.69개가 추출됐다.
5. **라벨·근거 부여** — 각 원자 주장을 정부 입장 구간과 대조해 3분류 라벨을 부여하고, 판정 근거가 된 정부 입장 문장을 원문 그대로 인용해 `evidence_sentence`에 넣는다. 인용된 문장이 정부 입장 구간에 실제로 존재하지 않으면 해당 주장을 폐기한다.

4~5단계는 `scripts/extract_claims.py`로 자동 수행하며, 스크립트의 기본 모델은 `claude-sonnet-4-6`이다.

## 필드 설명

### `data/dataset.jsonl` — 레코드 단위 (해명자료 1건 = 1줄)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `briefing_id` | string | 해명자료 고유 식별자 (상세 페이지 `newsId`) |
| `briefing_url` | string | 해명자료 원문 URL |
| `briefing_published_at` | string | 해명자료 게시일 (`YYYY-MM-DD`) |
| `ministry` | string | 해명 주체 부처·처·청·위원회 |
| `reported_press` | string | 해명 대상 보도의 언론사. 식별 실패 시 빈 문자열 (190건 중 135건 식별) |
| `reported_date` | string | 해명 대상 보도의 일자 (`MM-DD`). 식별 실패 시 빈 문자열 |
| `claims` | array | 해당 자료에서 추출한 주장 목록 |

### `claims[]` — 주장 단위

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `claim_id` | string | 주장 식별자. `{briefing_id}-{순번}` 형식 |
| `claim_sentence` | string | 검증 대상 주장 문장. 보도 내용 블록에서 원자 단위로 분해된 문장 |
| `claim_type` | string | `numeric` 수치·금액·비율 / `temporal` 시점·기간·순서 / `causal` 인과·영향 / `simple` 단일 사실 / `compound` 둘 이상 결합 |
| `label` | string | `SUPPORTED` / `REFUTED` / `NEI` |
| `evidence_sentence` | string | 판정 근거가 된 정부 입장 문장의 원문 인용. `NEI`인 경우 빈 문자열 |
| `evidence_url` | string | 근거 출처 URL (해당 해명자료 원문) |

### `data/eval_manifest.jsonl`

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `claim_id` | string | `dataset.jsonl`의 `claim_id`와 대응 |
| `gold_label` | string | 평가 기준 라벨. `dataset.jsonl`의 `label`과 동일 |
| `structure_stratum` | string | 주장 구조 층위. `single` 단일 구조 / `complex_candidate` 복합 구조 후보 |

## 라벨 정의

판정 기준은 **해당 해명자료의 정부 입장 구간**이다. 외부 지식이나 검색 결과는 판정에 사용하지 않는다.

| 라벨 | 판정 기준 |
| --- | --- |
| `SUPPORTED` | 정부 입장이 그 주장의 내용을 사실로 인정한다. 정부가 부분적으로 인정하는 경우("~은 사실이나 ~는 다르다")에는 인정된 부분에 해당하는 주장이 `SUPPORTED`가 된다. |
| `REFUTED` | 정부 입장이 그 주장을 부정하거나 사실과 다르다고 명시한다. |
| `NEI` | 정부 입장이 그 주장을 다루지 않아 판단 근거가 없다 (Not Enough Info). 이 경우 `evidence_sentence`는 빈 문자열이다. |

분포는 `SUPPORTED` 117건(22.9%), `REFUTED` 229건(44.7%), `NEI` 166건(32.4%)이다.

## 라벨 품질

라벨은 자동으로 부여한 뒤, 20개 표본을 저자가 직접 검토했다. 19건(95.0%)이 자동 라벨과 일치했다. 검수 기록 전체는 [`audit/label_audit_20.csv`](audit/label_audit_20.csv)에 있다.

## 제한 사항

- **라벨은 정부 공식 입장을 기준으로 한 대리 정답(proxy gold)이다.** 객관적 사실 여부에 대한 독립적 검증 결과가 아니라, 해당 부처가 그 보도 내용을 어떻게 규정했는지를 라벨로 옮긴 것이다. 정부 입장 자체가 논쟁의 대상인 사안에서는 이 구분이 중요하다.
- **주장 문장은 언론 보도 원문이 아니라 정부가 재서술한 형태다.** 보도 내용 블록은 각 부처가 해명을 위해 정리한 요약이므로, 원 기사의 표현·맥락·유보 조건이 그대로 보존되어 있다고 보장할 수 없다.
- **언론 기사 본문은 저작권을 고려해 포함하지 않았다.** 데이터셋에는 해명자료에 인용된 범위의 주장 문장만 담겨 있으며, 대상 기사의 전문이나 본문 발췌는 들어 있지 않다.
